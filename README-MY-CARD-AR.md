# ميزة «بطاقتي / My Card» — AKGYM

تمت إضافة واجهة بطاقة العضو إلى الموقع باللغتين العربية والإنجليزية، وتغيّر عناوين البطاقة وحالتها وتنسيق التاريخ مع لغة الموقع. تتضمن الواجهة التحقق برقم العضوية ورقم الموبايل المسجّل لدى النادي، والباركود، وإجمالي الجلسات والمستهلك والمتبقي، والباقة وتاريخ الانتهاء.

## مهم قبل النشر

**واجهة الموقع جاهزة، لكن جلب بيانات الأعضاء الحقيقية غير مفعّل افتراضياً**. لن تعرض الواجهة بيانات تجريبية على أنها بيانات لاعب. واجهة API ترجع `503` حتى يتم إعداد خدمة مزامنة موثوقة. لا تضع قاعدة SQLite المحلية أو كلمة مرور موظف الاستقبال على Vercel، ولا تفتح جهاز النادي للإنترنت.

## إعداد الربط

في إعدادات مشروع Vercel، أضف متغيري البيئة التاليين بعد تجهيز خدمة مزامنة HTTPS:

- `MEMBER_SYNC_API_URL` — عنوان خدمة المزامنة الآمنة، مثل `https://sync.example.com` (دون مسار `/member-card/login`).
- `MEMBER_SYNC_API_TOKEN` — سر طويل عشوائي مشترك، محفوظ في إعدادات الخادم فقط، وليس داخل ملفات الواجهة.

بعدها تعيد Vercel توجيه بيانات تسجيل الدخول إلى `POST {MEMBER_SYNC_API_URL}/member-card/login` مع `Authorization: Bearer <MEMBER_SYNC_API_TOKEN>`.

### عقد الخدمة المطلوبة

ترسل الواجهة للخدمة:

```json
{"memberCode":"AK-000123","phone":"REGISTERED_MOBILE_NUMBER"}
```

وعند نجاح التحقق فقط، يجب أن تعيد الخدمة:

```json
{
  "member": {"fullName":"Member Name","memberCode":"AK-000123","barcodeValue":"AK-000123"},
  "subscription": {"planName":"Monthly","endDate":"2026-12-31","status":"active"},
  "visits": {"total":30,"used":12,"remaining":18}
}
```

هذا المثال يشرح شكل الاستجابة فقط، وليس بيانات حقيقية. يجب على خدمة المزامنة مطابقة رقم العضوية ورقم الموبايل المسجّل مع بيانات العضو على الخادم، وتطبيق تحديد صارم للمحاولات ومراقبة محاولات التخمين، وإرجاع بيانات العضو المطابق فقط. تنبيه: هذا التحقق أسهل في التخمين من كلمة مرور أو رمز سري؛ لا تعرض بيانات حساسة عبر البطاقة، ومن الأفضل إضافة تحقق إضافي إذا كانت البيانات المعروضة حساسة.

## مزامنة آمنة موصى بها

- يبقى نظام الاستقبال وقاعدة SQLite داخل شبكة النادي.
- يرسل جهاز مزامنة داخل النادي اتصالاً صادراً عبر HTTPS فقط، ولا يتم فتح منفذ وارد على شبكة النادي.
- تُنشر إلى خدمة البطاقة أقل مجموعة بيانات لازمة فقط: رقم العضوية، الاسم المعروض، رمز الباركود، ملخص الاشتراك، عدادات الجلسات، والحد الأدنى من البيانات اللازمة لمطابقة رقم العضوية ورقم الموبايل على الخادم.
- لا تزامن الملاحظات الداخلية أو بيانات الدفع أو سجلات الموظفين.
- استخدم رموز دخول فردية قابلة لإعادة التعيين، وتحديد معدل المحاولات، وسجلات تدقيق، وتاريخ تحديث للمزامنة.

## اختبار بعد ربط الخدمة

1. رقم عضوية ورقم موبايل مطابقان: تعرض بيانات ذلك العضو فقط.
2. رقم موبايل خاطئ أو رقم عضو غير موجود: رسالة عامة لا تكشف وجود العضوية، وتُحتسب المحاولة ضمن حد المحاولات.
3. عضو ثانٍ: لا يمكنه رؤية بطاقة العضو الأول.
4. اشتراك منتهٍ أو لم يبدأ: تظهر الحالة الصحيحة.
5. اختبار الباركود على قارئ النادي للتأكد من أن قيمة `barcodeValue` تطابق الترميز الذي يتوقعه القارئ.
6. انقطاع خدمة المزامنة: تظهر رسالة تعذر الخدمة ولا تظهر بيانات قديمة على أنها محدثة.
7. تغيير لغة الموقع: تتحول العناوين والحالة والتاريخ بين العربية والإنجليزية.

## ملفات أُضيفت/عُدلت

- `index.html` — رابط بطاقتي/ My Card وقسم البطاقة.
- `style.css` — تنسيق البطاقة المتجاوب.
- `script.js` — الترجمة وتسجيل الدخول وعرض الحقول بأمان.
- `api/member-card.js` — نقطة وسيطة على Vercel، لا تكشف سر الخدمة للمتصفح.
